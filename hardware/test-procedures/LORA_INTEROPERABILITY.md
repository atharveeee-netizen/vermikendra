# Test Procedure: LoRa Interoperability Spike

## Context
**Status:** `UNVERIFIED`

The Vermikendra architecture specifies a RAK4631 (nRF52840 + SX1262) as the edge node and a Raspberry Pi CM4 with a Waveshare SX1262 LoRa HAT as the gateway. 

The integration risk here is critical:
- The **RAK4631** talks directly to the SX1262 silicon via SPI, giving us total control over the LoRa frame format via the `RadioLib` C++ library.
- The **Waveshare HAT** typically intercepts communications via an onboard microcontroller that accepts serial UART commands and translates them to SPI. 

We cannot assume the UART abstraction layer of the HAT will properly decode the raw binary P2P payload generated by RadioLib.

## The Spike Test

Before writing the complete C++ firmware or the Python ingest service, this specific hardware boundary must be proven.

### Step 1: Node Transmission (RAK4631)
1. Write a minimal Arduino/PlatformIO script using `RadioLib`.
2. Configure: `865.0 MHz`, `BW 125 kHz`, `SF 9`, `CR 4/5`, `Sync Word 0x12`.
3. Transmit a hardcoded byte array: `[0x01, 0xAA, 0xBB, 0xCC, 0xDD]`.

### Step 2: Gateway Reception (CM4 + HAT)
1. Write a minimal Python script using `pyserial` connected to `/dev/serial0`.
2. Configure the HAT to the matching frequency, BW, SF, and CR using its proprietary AT commands (or configuration registers).
3. Attempt to receive the packet.

### Acceptance Criteria
**PASS:** The Python script prints exactly `[0x01, 0xAA, 0xBB, 0xCC, 0xDD]` with no missing bits or proprietary headers injected by the HAT.

**FAIL:** The script receives garbage, receives nothing, or the HAT's microcontroller rejects the raw packet.

### Fallback Architecture (If FAIL)
If the Waveshare HAT UART abstraction is incompatible with raw RadioLib packets, the gateway architecture must be changed:
1. Ditch the Waveshare HAT.
2. Use a second RAK4631 plugged directly into the CM4 via USB.
3. The second RAK4631 will run a simple "LoRa-to-Serial Pass-Through" firmware using RadioLib, acting as a transparent modem for the Python daemon.
